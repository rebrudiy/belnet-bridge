# Обычный трафик для проверки DPI

Собираем реальные публичные страницы, загрузки и видео через отдельный Chrome.
Пользовательские профили и аккаунты не используются. Это набор отрицательных
примеров для локального эксперимента, а не статистика всего интернета.

До запуска зафиксированы 20 групп и 24 визита: Google Search, YouTube,
документация, загрузки. Разбиение 12 / 4 / 4 группы находится в `plan.json`.
Все соединения визита и его варианты default / TCP остаются в одном split.
Пилотные проверки доступности не участвуют в обучении или итоговом тесте.

После ошибок доступа отдельно зарегистрирован `amendment-001.json`: ещё
5 новых групп — Google homepage train / validation / test и Big Buck Bunny
через explicit TCP в validation / test. Итого 25 групп, 29 визитов.
Видео BBB совпадает с train: это проверка новых сессий, не независимого контента.
Прошлые неудачные попытки сохранены; повторения до успеха не выполнялись.

## Что подтверждает данные

- `out/dpi-v2/real/evidence.json`: результат каждого визита, версия Chrome,
  HTTP-протоколы, ошибки, media bytes и фактическое время воспроизведения.
- `observations.json`: пригодные начальные TLS/TCP окна успешных нагрузок.
- `late-observations.json`: отдельные окна через 5 и 10 секунд, если есть данные.
- `access-failure-observations.json`: соединения неуспешных нагрузок отдельно.
- В каталоге визита `flows.json` сохраняет причины исключения каждого TCP потока.

Видео считается подтверждённым только при `currentTime >= 2 s` и ответе media
HTTP 200 с минимум 10 000 переданных байт. Это не загрузка одной HTML-страницы.
CDP считает байты передачи ответа; часть HTTP overhead может входить в счётчик.
Ошибка видео и CAPTCHA не считаются успешной нагрузкой и сохраняются.

## Что видит модель

Берём только Chrome NetLog `SOCKET_BYTES_SENT/RECEIVED`: это байты TCP под TLS,
а не расшифрованные `SSL_*` события. Собираем полные outer TLS records, оставляем
тип 23 и передаём длину с пятибайтовым заголовком, направление и время callback.
Направление `+1` — клиент → сервер. Время округлено Chrome до миллисекунд.

Требуем успешный TCP connect, клиентский TLS handshake prefix, успешный TLS
и полные 2 секунды после первого type-23 record либо первые 64 records.
Не-TLS данные, потерянные raw bytes и слишком короткий prefix исключаются.
Поздние окна не смешиваются с начальными. TLS 1.3 type 23 включает также
зашифрованный handshake: длины сертификатов могут влиять на классификацию.

HTTP/3/QUIC записывается отдельными счётчиками. TLS/TCP модель QUIC не оценивает.
У `default` QUIC не отключён; только явно подписанный вариант `tcp` использует
`--disable-quic`. Визит YouTube с HTTP/3 не означает, что видео прошло TCP DPI.

## Повторение

Нужны Node с native WebSocket и Chrome по указанному в `browser.cjs` пути.
Ничего не устанавливается в пользовательский браузер.

```sh
node lab/dpi-v2/real/acquire.cjs
node lab/dpi-v2/real/acquire.cjs lab/dpi-v2/real/amendment-001.json
node lab/dpi-v2/real/extract.cjs
node lab/dpi-v2/real/extract.test.cjs
```

`acquire.cjs` продолжает незавершённый набор, не перезаписывая готовые визиты.
`plan.cjs` создал исходный план и откажется перезаписать его. Для нового
эксперимента нужен новый каталог и новое заранее назначенное разбиение.

Сырые NetLog и временные профили находятся только в `private/` и не публикуются:
NetLog Everything может содержать анонимные cookies и HTTP headers. Открытая
сводка удаляет signed media URL query и служебные параметры. SHA-256 сырого
NetLog позволяет сверить происхождение, не публикуя его содержимое.

## Ограничения

Мало независимых групп; сотни соединений не равны сотням независимых пользователей.
Счётчики отдельных потоков и групп следует показывать раздельно. Все браузерные
примеры — один Chrome / macOS / один egress; Go wrapper использует другой TLS
stack. Нужны локальные обычные нагрузки на том же сервере и сертификате, чтобы
модель не училась отличать Chrome от Go. Визит включает startup/background
соединения свежего Chrome; это не чистая изоляция одного origin. Разные страницы
не доказывают независимость origin, сети и TLS fingerprints.

Из этой выборки нельзя делать вывод о коммерческом DPI, блокировках провайдера
или гарантированном обходе. FPR и detection считает основной эксперимент после
фиксации модели; этот сборщик не подбирает классификатор или threshold.
