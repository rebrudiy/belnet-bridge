# DPI v2: заранее заданная проверка

Дата: 2026-11-19. Seed: 2026111907. Старые 15 итераций и crosscheck неизменны.

Цель — измерить переносимость обнаружения на разнообразный нормальный трафик,
а затем проверить транспорт с новым обученным противником. Успешный HTTP-запрос
после переподключения не означает, что DPI не обнаружил соединение.

Разбиение назначается до генерации: полная браузерная сессия или запуск нагрузки
со всеми его соединениями принадлежит только одному split. Train / validation /
test — разные сессии; внешние браузерные семейства и локальные не-echo нагрузки
показываются отдельно. Не подбирать threshold по test. Бюджет калибровки FPR ≤5%;
фактический test FPR сообщать даже при нарушении бюджета. Небольшая выборка не
доказывает FPR для реального провайдера.

Контроли: Google Search, настоящее воспроизведение YouTube с подтверждением
media bytes/playback, обычные страницы и загрузки; локальные download, upload,
server push, смешанный чат, асимметричный RPC на том же TLS endpoint и сертификате.
QUIC фиксируется отдельно: TLS-over-TCP классификатор его не оценивает.
Ошибки доступа, неполные TLS записи и отсутствующее видео не считать успехом.

Обе метки сравниваются по клиентским наблюдениям TLS record length / direction /
callback time; Chrome NetLog и Go socket observer — разные стеки. Результаты
по стекам/семействам отдельно; внешний браузер не должен становиться единственным
отрицательным классом. Начальные и поздние окна оцениваются раздельно, если
доступен полный поток записей. IP, SNI, payload не являются признаками модели.

Baseline — неизменённый v2. Экспериментальный v3: равные по размеру poll/reply
ячейки, фрагментация UDP, немедленный ответ из очереди либо dummy. Это гипотеза,
не доказательство маскировки. Указать частоту, лишний трафик, ожидание/отбрасывания.
Старый предел задержки 100 ms и множитель 8x для этого режима не гарантируются.
Готовый открытый транспорт также рассматривается как отдельный baseline.

Противник: frozen старый forest плюс новый forest после фиксации кандидата.
Detection, принудительное закрытие и работоспособность BelNet — три отдельных
показателя. Дополнительный режим сохраняет положительный вердикт на 30 секунд
для client IP + entry; это проверяет зависимость результата от повторных входов.

Сохранять все попытки, ошибки и промежуточные измерения. Нельзя выдавать неполные
наблюдения за обход, менять labels/threshold по результату final либо замещать
реальное видео синтетическим стримом.
