# Проверка завершения capture под нагрузкой

Два заранее заданных development-случая: обычный WSS/RPC и UDP-эхо через
framer + REALITY. По 5 секунд нагрузки, остановка активных CONNECT-туннелей,
500ms drain, остановка tcpdump. Это проверка стенда, без BelNet и внешней сети.

Запуск dev-01 завершён, повторных попыток нет:

| Проверка | WSS | REALITY + UDP |
|---|---:|---:|
| Записано / received by filter | 64 / 64 | 372 / 372 |
| Kernel drops / TCP sequence gaps | 0 / 0 | 0 / 0 |
| Активных туннелей закрыто | 1 | 1 |
| Прокси остался запущен; новый CONNECT → 503 | да | да |
| Байты up: proxy / wire | 10022 / 10022 | 208796 / 208796 |
| Байты down: proxy / wire | 26384 / 26408 | 208467 / 208491 |

В обоих PCAP есть последний 24-byte TLS record с заголовком `1703030013`.
Он наблюдался через 298µs / 397µs после начала quiesce, пока операция ещё шла.
Сеть получила эти байты, прокси клиенту их не передал. Внутреннее содержимое
TLS не расшифровывалось: называть этот record конкретным alert нельзя.

Исходный строгий gate требовал равенства всех forwarded/wire байтов, поэтому
**qualified=false сохранён**. Совпадение packet counters полезно для следующего
протокола; оно не превращает этот запуск в полностью прошедший.
В следующем freeze полноту capture и потери при намеренном завершении нужно
учитывать отдельно, с границей по VM-времени. Результат обхода DPI здесь не измерялся.

Артефакты: [summary.json](../../../out/dpi-g03/quiesce-preflight/dev-01/summary.json),
`ordinary/tail-analysis.json`, `reality/tail-analysis.json` в том же каталоге.
8 исходных runtime-файлов архивированы с проверкой pre-run SHA.
Контейнеры и отдельная internal-сеть удалены; существующие узлы не менялись.

```sh
node --test lab/dpi-g03/quiesce-preflight/wire.test.cjs
node lab/dpi-g03/quiesce-preflight/run.cjs NEW_DEV_ID
```

Команда создаёт отдельную internal-сеть `172.30.93.0/24` и два собственных
контейнера; запрещает повторное использование ID. 10.88.0.11 — alias только
в новом origin namespace, чтобы использовать неизменённый allowlist helper.
Capture ограничен 16MiB; ожидания процессов ограничены по времени.
Последующий запуск возвращает 2 при `qualified=false`; исторический dev-01
вернул 0 после сохранения результата. Его исходный код остаётся в `source/`.
